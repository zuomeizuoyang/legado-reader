# 书源阅读 · 自托管版

把「阅读」（Legado）的书源搬到网页上跑。自己找台机器起服务，手机、平板、电脑用浏览器打开就能搜书、看书，不用装 App。

**这个项目只包含程序：不含任何小说内容，不含任何书源，也不提供公共实例。** 每个人的书架、阅读进度、导入的书源都只存在自己那台机器上，互相看不见。

---

## 开始之前

| 需要的 | 说明 |
| --- | --- |
| 一台机器 | VPS、NAS、树莓派、家里不关的旧电脑都行；能跑 Docker 最省事 |
| 一点命令行基础 | 下面每个步骤都是可以直接复制的完整命令 |

**不适合你的情况：**

- 想开箱即用、点开就能看 —— 这里没有公共站点，必须自己部署一次
- 想看正版付费书 —— 引擎不碰付费墙，也不保存登录态，所有源都以游客身份访问
- 完全不想碰命令行 —— 建议直接跳过，别折腾

## 五种用起来的方式

| 你的情况 | 怎么开始 |
| --- | --- |
| 有 Node 环境（推荐） | 「方式一」，装个依赖就能跑 |
| 有 Docker / VPS | 「方式二」，两条命令 |
| 想让 AI agent 代劳 | 把仓库地址丢给它，说「照 `AGENTS.md` 部署」。仓库根的 `AGENTS.md` 就是写给它的说明书 |
| 用 DeepSeek Harness | 装 [`dsh-plugin/`](./dsh-plugin)，agent 多一个 `legado_deploy` 工具 |
| 用 WorkBuddy / Claude Skill | 拿 `SKILL.md` 做成技能，一句话触发部署 |

懒人版，一条命令（Linux / macOS）：

```bash
curl -fsSL https://raw.githubusercontent.com/zuomeizuoyang/legado-reader/main/install.sh | bash
```

装完会打印带口令的地址。想要参数就 `| bash -s -- --port 8080 --dir ~/books`。

## 方式一：直接跑（推荐）

需要 Node.js 18 或更高。不用装 Docker，也不用拉镜像。

```bash
git clone <仓库地址> legado-reader
cd legado-reader
npm install

DATA_DIR=~/legado-data PORT=8899 node server.mjs
```

打开 `http://127.0.0.1:8899` 就能用，**不需要口令、不会弹框**。手机可以「添加到主屏幕」当 App 用。

两个环境变量：

| 变量 | 作用 | 不写会怎样 |
| --- | --- | --- |
| `DATA_DIR` | 书架、进度、书源放哪 | 塞进代码目录，升级或重装就没了 |
| `PORT` | 监听端口 | 默认 3000 |

**要放到公网才需要口令：**

```bash
DATA_DIR=~/legado-data ACCESS_KEY=你的口令 PORT=8899 node server.mjs
```

之后访问带 `?k=你的口令`，例如 `http://你的IP:8899/?k=xxx`。不设的话，任何能访问到端口的人都能把这台机器当抓取代理。

跑起来想更新：`git pull` 后重启进程即可，数据在 `DATA_DIR` 里不受影响。

想长期挂着，用 systemd 或 pm2 托管；前面套一层 Nginx 做 HTTPS 更稳。

**Windows**：用 PowerShell 设好环境变量再启动：

```powershell
$env:DATA_DIR="D:\legado-data"; $env:PORT="8899"; node server.mjs
```

## 方式二：Docker

不想装 Node，或者想用容器管数据卷，走这条。

```bash
git clone <仓库地址> legado-reader
cd legado-reader
docker compose up -d
```

不用 `docker login` —— 镜像是公开的，直接拉。

看到容器起来后，浏览器打开 `http://你的机器IP:8899` 就能用，**不需要口令、不会弹框**。

> 拉取约 53MB，落地约 160MB，其中 46MB 是 Node 运行时本身。基于 alpine，运行期只需 Node 与 59 个 npm 包。

**要放到公网才需要口令：**

```bash
cp .env.example .env
vi .env                    # 写一行 ACCESS_KEY=你的口令
docker compose up -d       # 重启生效
```

之后访问带 `?k=你的口令`，例如 `http://你的机器IP:8899/?k=xxx`。

**升级到新版本：**

```bash
docker compose pull
docker compose up -d
```

数据在 volume 里，升级不会动。

## 你的数据在哪

| 内容 | 直接跑 | Docker |
| --- | --- | --- |
| 书架、阅读进度 | `$DATA_DIR/state.json` | `./legado-data/state.json` |
| 当前生效的书源 | `$DATA_DIR/classic.json` | `./legado-data/classic.json` |

**备份**就是打包这个目录，一个文件都不多：

```bash
tar czf legado-backup-$(date +%F).tar.gz "$DATA_DIR"    # 直接跑
docker cp legado-reader:/data ./legado-backup && tar czf legado-backup-$(date +%F).tar.gz legado-backup   # Docker
```

**迁移**到新机器：把目录拷过去，指给 `DATA_DIR`（或挂到容器的 `/data`），起来就是原来的样子。

换一台设备用（比如从手机换到电脑）**不需要**拷数据 —— 服务端那份 `state.json` 是各设备书架对齐的锚点，同一个服务下不同浏览器会自动同步。

## 安全（重要）

`ACCESS_KEY` 不是可选项。这个服务会替访问者向外网发请求，不设口令就等于把你的服务器开放成一个公共抓取代理：

- 别人可以用你的 IP 去抓任何东西，封 IP、投诉、法律风险都记在你这台机器上
- 带宽和流量也算你的

启动时如果检测到「监听全部网卡但没设口令」，控制台会打印醒目警告。**看到警告就去补 `ACCESS_KEY`。**

反代的话，注意别把 `?k=` 参数在日志里明文打出来。

## 书源：本仓库一个都不带

**这个仓库里没有任何书源。** `data/classic.json` 是个空数组，首次启动不会给你铺任何东西。这是故意的。

打开网页底部「书源」→「导入」，两种方式：

- **粘 JSON**：把你自己手上的 Legado 书源 JSON 贴进去
- **粘订阅链接**：下载和解析都在服务端做，不受浏览器跨域限制，几 MB 的整合包（几百个源）一次能吃下

导入成功会看到「书源 +N」的回执，下载耗时实时显示。

**为什么不内置：** 书源指向的是具体站点和具体内容，能不能用取决于当天站点的状态，作者没法替你维护，也不该替你挑。这个项目只提供执行规则的那套引擎，以及一个能好好看书的界面。

> 书源从哪来、能不能用、是否合规，需要你自己判断，见下方「免责」。

## 搜索慢是正常的

几百个源**全量并发搜**，一轮通常 2–5 分钟。这不是卡住：

- 活源中位响应 0.3 秒，死源会拖到 18 秒超时
- 边搜边出结果，状态栏能看到 `已完成 137/349`
- 随时可以点「停止」，已经拿到的结果保留
- 报错的源会记成失效，下次搜索跳过（**「零结果」不算失效**，只是那个源没这本书）

结果按书名相关性排序：完全一致 → 包含关键词 → 字全出现 → 其他。有精确命中时默认只显示命中，标题栏可以点开看全部。

## 常见问题

**起点、晋江这类源用不了？**
引擎不保存登录态，所有请求都是游客身份。需要登录才能看的内容拿不到。

**图片加载不出来？**
图片走服务端代理（带 Referer 绕防盗链）。某些源本身就限制外链，这种情况没办法。

**目录顺序乱了？**
后端会按章节序号重排（阿拉伯数字和中文章节号都认），但检测到编号重复（分卷重新计数）时会保持原样，宁可不排序也不搅乱站点自己的结构。目录抽屉里有「⇅」可以手动反转。

**换设备书架空了？**
书架存了两份：浏览器本地一份，服务端 `state.json` 一份。同一个服务地址下会自动对齐；换了服务地址（比如换了域名）就是新环境了。

<summary>给开发者的实现说明（点开）</summary>

书源规则里有大量 `@js:` 脚本，靠 `java.ajax()` 抓数据、`org.jsoup` 解析页面。浏览器里没有这些东西 —— 不是权限问题，是能力问题。加上跨域限制，纯前端方案只能跑零头：实测抽样 24 个源，**88% 含 JS 规则，纯前端只跑得动 12%**。

所以这套东西必须有个后端，Node 上做了完整仿真：

| 能力 | 纯前端 | 本项目 |
| --- | --- | --- |
| 跨域抓取 | 靠公共代理，国内基本全废 | 服务端直连 |
| `@js:` 规则 | 直接跳过 | vm 沙箱执行 |
| `java.ajax()` 同步调用 | 不支持 | Atomics 阻塞桥 |
| `org.jsoup` 解析 | 不支持 | jsdom 包装 |
| GBK / Big5 编码 | 勉强 | iconv 精确解码 |
| 图片防盗链 403 | 不支持 | 服务端带 Referer 重取 |

入口 `server.mjs`（HTTP + 静态资源 + API），`src/` 下分三块：`jsengine` / `rules` / `book`（规则引擎与解析）、`proxy` / `ssrf` / `syncfetch`（抓取与出网校验）、`feed`（发现流）。

</details>
